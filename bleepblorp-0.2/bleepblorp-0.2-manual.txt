3. TROUBLESHOOTING
==============================================================================

Symptom: "npm is not recognized"  OR  Start-bleepblorp.bat says Node is missing
  Node is not installed, or this window was open before you installed it.
  Close it, reopen, run:  node -v    and    npm -v
  You want v20 or newer.

Symptom: "package.json not found" / npm ENOENT package.json
  You are one folder too high. Open the folder that contains START HERE.txt
  and package.json together.

Symptom: npm install fails (network / permissions / OneDrive)
  Unzip to C:\bleepblorp-0.2 (not Desktop, not OneDrive Documents).
  Corporate VPN / Pi-hole can block the npm registry.

Symptom: npm run build runs out of memory (especially a 1 GB VPS)
  In the same terminal, then rebuild:

    set NODE_OPTIONS=--max-old-space-size=768     (Windows PowerShell: see below)
    $env:NODE_OPTIONS="--max-old-space-size=768"  (PowerShell)
    export NODE_OPTIONS=--max-old-space-size=768  (Mac/Linux)
    npm run build

Symptom: http://localhost:3000 will not load
  * Confirm the terminal still shows the server running.
  * Try http://127.0.0.1:3000
  * Another app may own port 3000. Stop it, or start with:
      npx next start -H 127.0.0.1 -p 3001
    then open http://localhost:3001

Symptom: Dashboard says SSE·off or looks frozen
  Hard-refresh the tab (Ctrl+F5). Only keep 1–2 tabs open. Each tab is a live
  stream. If the page sat in the background, just refresh.

Symptom: SSE·on but ·approx instead of ·CFB
  Kalshi websocket / official RTI is not connected. Usually missing or invalid
  API keys. The bot can still run on approximate spot. Fix credentials
  (section 4), restart, wait ~15 seconds.

Symptom: Markets stuck at 0:00 with $1.00 asks
  Kalshi 15m rollover / strike TBD. Wait one refresh cycle (a few seconds) or
  restart once. Weekly crypto 15m gap: about Wednesday 11:45pm to Thursday
  2:00am Pacific — those windows simply do not exist. The bot is not broken.

Symptom: "No Kalshi API key" in status
  Expected until you add keys. Public REST still discovers markets.

Symptom: Paper scoreboard never moves
  Mid-market only buys when its gates fire (often a few times per hour, not
  every minute). End-of-market only papers in the last 8 minutes when the
  bid is 85–98c and finish confidence is at least 85%. Empty is normal on a
  quiet tape.

Symptom: Rec PnL / SL/TP columns show "—"
  The optimizer needs enough path-complete paper fills (about 12 to show
  anything, 20+ before end-of-market leaves the live 49c protocol fallback).
  After a fresh install this takes time. The app also spawns the helper after
  each completed path. You can run   npm run exit-opt   yourself.

Symptom: Antivirus deleted node or the project
  Restore the folder, add an exclusion for your bleepblorp-0.2 directory and
  for Node.js. This is local educational software, not a downloaded "bot.exe".

Symptom: I exposed the dashboard on the public internet
  Stop doing that. Bind localhost or use an SSH tunnel (section 5).
  Anyone who can POST /api/performance can wipe YOUR paper journal. There is
  no password on that endpoint.

Still stuck: copy the last 30 lines of the terminal (no API keys) and ask in
Strategist chat. Do not paste private keys, .env.local, or PEM files.

4. CONNECT YOUR KALSHI API
==============================================================================

Keys let the bot use Kalshi's official websocket: CF Benchmarks RTI (the same
family of index Kalshi uses to settle) plus live Up/Down books.

bleepblorp 0.2 uses the key only to READ public market data. It does not
submit orders. Even so, treat the private key like a password. Never put it
in email, Discord, OBS, or a screenshot.

4.1 Create the key on Kalshi

  1. Log in at https://kalshi.com
  2. Open account / API settings (Kalshi's labels move; look for API keys).
  3. Create an API key. Kalshi will show an API Key ID and a private key
     (PEM), often RSA.
  4. Download / copy them ONCE. Store the private key off-screen.

  If Kalshi shows a Python snippet, it often looks like:

    API_KEY_ID = "your-key-id"
    PRIVATE_KEY = """
    -----BEGIN RSA PRIVATE KEY-----
    ....
    -----END RSA PRIVATE KEY-----
    """

  That file format is exactly what bleepblorp expects.

4.2 Option A — credentials file (best while streaming)

  Save the Python-style file somewhere that is NOT inside the project folder,
  for example:

    C:\Users\YOURNAME\Documents\kalshi-keys.py

  In .env.local set:

    BLEEPBLORP_STANDALONE=1
    KALSHI_CREDENTIALS_FILE=C:\Users\YOURNAME\Documents\kalshi-keys.py

  Use YOUR path. Quotes are not required unless the path has spaces; if it
  has spaces you may put the whole path in quotes depending on the editor.
  A path without spaces is simpler.

4.3 Option B — values in .env.local

    BLEEPBLORP_STANDALONE=1
    KALSHI_API_KEY_ID=your-key-id
    KALSHI_PRIVATE_KEY=-----BEGIN RSA PRIVATE KEY-----\n....\n-----END RSA PRIVATE KEY-----

  Newlines in .env can be written as \n. Option A is easier.

4.4 Restart and check

  Stop the bot (Ctrl+C), start it again, open http://localhost:3000
  Header should move from ·approx toward ·CFB when the websocket is up.
  You can also open http://localhost:3000/api/status
  Look for credentialsConfigured true and kalshiWs.connected true.

4.5 If auth fails

  * Did you restart after editing .env.local?
  * Is the PEM complete (BEGIN and END lines)?
  * File option: the parser looks for API_KEY_ID = "..." and PRIVATE_KEY = """..."""
  * Revoke a leaked key on Kalshi immediately and make a new one.

7. MID-MARKET STRATEGY — HOW IT WORKS AND WHY
==============================================================================

Disclaimer again: this is a research description of the paper rules in this
build. It is not a claim that the edge will persist, and it is not advice
to trade it live.

7.1 The job

  Each Kalshi 15-minute contract pays $1.00 if that coin's settlement index
  finishes at or above the window strike (Up), or $0 if it does not (then
  Down pays). Mid-market is NOT trying to call the final settlement with
  95% confidence. It is trying to buy a contract that still has ROOM TO
  REPRICE by about +20 cents before time runs out, when short-horizon
  indicators say a run is already underway.

  Think: "this Up contract is 48c, momentum is already on the Up side of
  the strike, can it trade 68c before the window dies?" — not "will BTC
  finish the day higher."

7.2 Inputs

  Spot         CF Benchmarks RTI when keys work; otherwise approximate
  Strike       Kalshi's strike for this 15m ticker
  Book         Up/Down bid and ask
  ATR          Wilder ATR(14) on only the last 15 one-minute CFB bars
               (rolling). Same recent window no matter how long the process
               has been up. A relative floor (~1.5 bps of spot) avoids fake
               zero-vol.
  Stoch RSI    momentum / washout
  Bollinger    stretch vs a short mean
  Lean         combination of Stoch + bands into a direction and a kind:
               momentum, mean-reversion, mixed, or none. Mean-reversion
               mid-market is PARKED in this build. Only momentum
               continuation is allowed to paper.

  Remaining-time volatility:

    sigma_T = ATR_1m * sqrt(seconds_left / 60)

  Hit odds ask: if we lean in a direction, where does spot need to go for
  the contract to gain +20c, and how plausible is that given sigma_T and
  the lean.

7.3 Live paper gates (this build)

  Time left          at least 6:00 (360 seconds). Late mid-market fills
                     bled expectancy in prior paper study.
  Lean kind          momentum continuation (not mixed, not reversion)
  Side               follows the lean (Up if lean >= 0, else Down)
  Geometry           spot already on that side of the strike, by 2–15 bps.
                     No trade if the run has not started (<2 bps) or is
                     already extended (>15 bps).
  Stoch confirm      Up: Stoch K >= 45
                     Down: Stoch K between 25 and 55
                     (blocks washed-out downs that kept losing in study)
  Ask                at least 35c, not fully priced (~100c)
  Spread             at most 10c
  Take-profit        fixed +20c. No stop. Sizing ladder is off.
  Hit bar            about 75% while the 6:00+ window is open, else 80%
  Asleep tape        if ATR/spot is too thin, mid-market sits out (slow
                     slides fake Stoch leans)

  When those pass, the box reads Buy. The paper engine opens one ticket
  per momentum episode (a Wait unlights the episode so the next Buy can
  be a new fill). Sticky logic ignores one-tick flickers so a single dip
  under the hit bar does not spam tickets.

7.4 How paper exits

  * Hit: contract mark reaches entry + 20c.
  * Else: last mark at window end (including ugly prints).
  * No stop. A loser can travel a long way. That is why the ask floor,
    time floor, and hit bar exist — they are risk controls, not magic.

  After flatten, the bot still records the path to expiry so Rec PnL can
  ask "what if we had used a different exit?" Mid-market Rec is still
  pinned to no-stop / +20c so the column matches the live paper rule.

7.5 Why this shape (research story, not a guarantee)

  Earlier protocols tried a tight 45–52c band, +10/+15/+20 ladders, and a
  mean-reversion lane. In this project's paper history:

    * Sub-35c "lottery" tickets were poor.
    * Mean-reversion mid-market stayed negative on crypto and was parked.
    * A short +10c target was often left on the table versus +20c when the
      path actually existed — so live mid-market was locked to +20c / no
      stop for this epoch.
    * Buying after the run had already extended (large cushion vs strike)
      chased exhaust. The 15 bps cap is there for that.
    * Entries inside the last six minutes were weaker for this scalp job;
      that time is left to end-of-market.

  None of that means the next month will look the same. Markets change.
  The scorecard is how you watch whether THIS epoch still behaves.

7.6 Why it can look "wrong" on stream

  A Buy can fail immediately. ATR can be calm then jump. Books can be
  one-sided. The model uses a normal-ish mapping from contract price to
  spot; real microprice is messier. Treat every mid-market Buy as a
  hypothesis with a 20c target, not a sure thing.

8. END-OF-MARKET STRATEGY — HOW IT WORKS AND WHY
==============================================================================

Again: educational description of the paper rules. Not advice to copy-trade.

8.1 The job

  Late in the 15 minutes, if the coin is already a cushion away from the
  strike versus remaining noise, the expensive side of the contract (high
  80s / 90s) is the market's way of saying "this is likely finished."
  End-of-market asks: is our finish probability high enough, and is the
  joinable bid still in a sane band (85–98c), to paper that side.

  This is a FINISH bet, not a scalp. Marks can draw down hard (MAE) even
  on tickets that expire as winners. Ugly paths are normal.

8.2 Finish probability

  Using rolling 1-minute ATR (same rolling last-15m CFB ATR as mid-market):

    sigma = ATR_1m * sqrt(t / 60) * asset_multiplier
    P(Up) = Phi( (spot - strike) / sigma )

  Phi is the standard normal CDF.

  Asset multipliers (majors jump more than a 1m ATR-normal suggests):

    BTC 1.35    ETH 1.25    SOL 1.00    XRP 1.00

  A light indicator blend is mixed in early and FADES as time runs out so
  that late confidence is mostly price-vs-strike, not Stoch.

  Safety: cushion / sigma. If that is under 0.5, confidence is forced below
  the 85% buy bar — too close to a coin flip vs remaining noise.

  Market respect: model confidence may not run far above the live Kalshi
  mid on that side (about +6c on BTC/ETH, +10c on SOL/XRP). A huge gap vs
  the book is treated as OUR miscalibration, not free edge.

8.3 Box lighting vs paper buy

  Highlight (thesis) when finish confidence >= 85%, even BEFORE 8:00 or
  if the bid is not yet in band. That is "watching," not a paper fill.

  Paper Buy when ALL of these hold:

    * seconds left <= 8:00 and > 1 second
    * best bid on the chosen side is between 85c and 98c (maker-style;
      alts often show a wild ask while the joinable bid is still legal)
    * confidence still >= 85% after safety clamp and market-respect cap

  Bid above 98c with thesis intact -> Hold (no new entry). You are not
  paid enough extra for the last couple of cents vs tail risk.

  Final second: no new entries; open paper is force-settled.

8.4 Live paper stop (end-of-market only)

  If entry is at least 80c, paper stop mark is 49c.
  Otherwise paper stop is 50% of entry.

  That is the LIVE paper rule, not necessarily the optimizer's long-run
  favorite. Rec PnL will keep showing 49c/hold until enough full paths
  exist to trust a grid search, then it may recommend a different pair.
  Rec is counterfactual. It is not money you "already made."

8.5 Why this shape (research story, not a guarantee)

  * Cheap late contracts are a different trade (lotteries). The 85c floor
    keeps the book in "already likely" territory.
  * Buying 99c+ with a 49c stop has awful payoff asymmetry.
  * The 8:00 open (and, in this epoch, staying open until the end instead
    of cutting off at 2:00) is the window where finish geometry is actually
    informative. Earlier, sigma is large and P(finish) is mushy.
  * Market-respect exists because a model that says 96% while the book is
    70c is usually wrong, not a genius.
  * Rolling ATR keeps two processes (or a restart) from disagreeing just
    because one had a longer candle history.

  End-of-market can still lose on a last-minute spike through the strike.
  That is the trade.

8.6 Mid vs end — different jobs

  Mid-market:  plenty of time, medium-priced contract, +20c scalp, no stop.
  End-of-market: little time, expensive contract, finish, 49c/50% paper stop.

  They can disagree. That is allowed. Do not "average" them into one click
  without understanding which job you are doing.
